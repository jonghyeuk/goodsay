# 실제 판매로 전환하기

현재 버전은 결제가 불가능한 체험/샘플 서비스입니다. 프런트엔드의 비활성 구매 버튼을 켜는 것만으로 판매를 시작해서는 안 됩니다.

## 연결할 서비스와 서버 책임

1. **판매자·고객지원 정보:** 실제 운영 주체, 문의 경로, 상품 구성·가격·보관기간·환불 기준을 결정하고 화면에 반영합니다.
2. **연락처 인증:** SMS 또는 이메일의 소유 확인을 구매 복구 수단으로 사용합니다. 인증 코드에는 유효기간·횟수 제한·재요청 간격이 필요합니다. 클라이언트에서 임의로 인증 성공을 만들지 않습니다.
3. **결제:** 판매자가 사용할 수 있는 결제 제공자와 계약합니다. 금액/상품은 서버에서 결정하고, 서버 검증 및 서명 확인한 웹훅만 결제 완료로 인정합니다. 주문 생성·결제 통지·생성 작업은 멱등 처리합니다.
4. **개인 해설:** 실제 사주/점성술 계산 도구의 상용 이용 조건을 확인하고 계산 기준·달력·시간대·시간 미상 처리를 명시합니다. LLM에 출생차트 계산 자체를 맡기지 않습니다. 현재 문답형 결과를 사주 기반 개인 분석으로 표시하지 않습니다.
5. **결과 저장/복구:** 주문·결과는 서버에서 접근 제어합니다. 이름/생년월일/추측 가능한 주문번호만으로 열람하지 않습니다. 연락처 확인 후 한정된 열람 토큰을 발급하고 공개 공유 링크와 구분합니다.
6. **실패/환불:** 생성 실패 재시도 한도, 결제 완료 후 미제공 탐지, 자동/수동 환불 절차를 마련합니다. 오류 로그에 원문 개인정보·인증 코드·결제 토큰을 남기지 않습니다.

## API 계약 초안

현재 `scripts/serve.mjs`는 아래 미연결 기능을 모두 차단하며 개인정보 본문을 저장/분석하지 않습니다.

- `GET /api/status`: 기능별 연결 상태. 현재 전부 false.
- `POST /api/checkout`: 추후 인증된 게스트 세션과 서버 상품 ID로 주문을 생성합니다. 현재 503.
- `POST /api/orders/restore`: 추후 연락처 소유 확인을 거친 세션으로 주문을 복구합니다. 현재 503.
- 결제 제공자 webhook: 추후 서명 검증·중복 수신 처리를 구현할 서버 전용 경로.

실제 운영 키는 서버 환경변수/시크릿 저장소에만 넣습니다. 공개 저장소·브라우저 번들·빌드 산출물에 넣지 않습니다. 실제 서버를 연결한 뒤 프런트의 준비 상태 표시와 관련 안내문을 함께 갱신합니다.

## 출시 전 검증

- 휴대폰 실기기에서 읽기·입력·결제창 복귀·재열람·파일 저장 확인
- 새로고침/중복 요청에도 중복 결제 및 주문 유실이 없는지 확인
- 타인의 주문 접근·공유 링크로 개인 결과 유출이 불가능한지 확인
- 실제 해설 계산 기준/결과와 영어판 지역·시간대 기준 검토
- 취소·환불·미제공 상황의 처리, 보관기간·삭제 요청 동선 확인

## 업데이트가 적은 운영

초기 유료 상품은 단건 해설 한 가지로 제한하고, 자유 채팅·추가 상담·맞춤 수정·가족 계정·일일 유료 구독은 넣지 않습니다. 새해 상품·선물 코드는 구매 수요와 운영 비용을 확인한 뒤 별도로 추가합니다. 좋은글은 검수한 오리지널 원고 모음을 자동 순환합니다.
