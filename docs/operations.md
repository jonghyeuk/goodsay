# 운영자 사용 설명서

## 지금 운영할 수 있는 범위

공개 주소: https://education-news-site.web.app

현재는 **무료 콘텐츠·체험 사이트**입니다. 광고가 없고 결제가 비활성 상태여서 현재 버전 자체에서는 매출이 발생하지 않습니다. 사주·점성술 계산이나 개인별 유료 보고서 생성도 아직 없습니다. 네 문항 결과를 유료 개인 분석 상품으로 판매하지 않습니다.

## 방문자가 쓰는 방법

| 하고 싶은 일 | 조작 |
| --- | --- |
| 오늘의 좋은글 읽기 | 홈 → 오늘의 글 읽기 |
| 다른 주제의 글 찾기 | 하단 좋은글 → 마음돌봄/관계/쉼/새로운 시작 선택 또는 검색 |
| 글 간직하기 | 글의 책갈피 누르기 → 하단 보관함에서 재열람 |
| 글을 친구에게 보내기 | 글 상세 → 마음 나누기 → 카드 확인 → 공유/이미지 저장/공개 링크 복사 |
| 글을 소리로 듣기 | 글 상세 → 읽어주기. 지원하지 않는 기기에서는 안내 표시 |
| 성향 체험 | 나를 알아보는 시간 → 네 문항 답하기 → 결과 확인 |
| 체험 결과 다시 보기 | 마지막 질문에서 이 브라우저에 저장 선택 → 보관함 |
| 해설서 구성 보기 | 나의 해설 → 전체 샘플 읽기 |

보관함은 회원 계정이 아니라 **현재 기기·현재 브라우저의 저장 공간**입니다. 카카오 내부 브라우저와 Chrome에서 각각 별도로 보일 수 있습니다. 브라우저 데이터를 지우면 사라집니다. 공개 글 링크는 친구가 볼 수 있지만 개인 구매 결과를 공유하는 기능은 없습니다.

## 좋은글 운영

현재 직접 작성한 원고 24편이 포함되어 있습니다. 한국 시간 자정에 날짜 기준으로 한 편을 골라 보여줍니다. **매일 AI가 새 글을 쓰는 기능이 아니라, 등록한 글을 순환하는 방식**입니다.

### 현재 추가 방법

관리자 글쓰기 화면은 아직 없습니다. 현재 원고는 `data.js`의 `seeds`에 보관합니다. 코드를 직접 다루기 어렵다면 다음 원고 양식으로 여러 편을 한 번에 준비하고 저장소 반영·배포를 요청할 수 있습니다. 이는 임시 운영 방식이며, 화면에서 직접 발행하려면 관리자 기능이 필요합니다.

```text
제목: 오늘의 작은 기쁨
주제: 마음돌봄 / 관계 / 쉼 / 새로운 시작 중 하나
카드에 넣을 문장: 두세 줄의 짧은 좋은글
본문: 방문자에게 전할 글
마무리 질문: 나를 돌아보는 질문 한 개
사진: forest 또는 blossom
```

개발자가 반영할 때 각 글은 고유한 `letter-25` 같은 ID를 사용합니다. 기존 ID는 바꾸거나 다른 글에 재사용하지 않습니다. 새 글을 앞에 추가하거나 순서를 바꿔도 기존 공유 링크·책갈피가 다른 글로 바뀌지 않도록 고정 ID를 사용합니다. 글 본문은 직접 작성하거나 이용 권한을 가진 원고만 사용합니다.

수정 후 검사·배포:

```bash
npm run check
npm run deploy:firebase
```

GitHub 자동 배포는 Firebase 서비스 계정 시크릿을 등록한 뒤 사용할 수 있습니다. 자세한 연결은 `docs/firebase.md`를 참고하세요.

### 권장 원고 준비 주기

처음에는 원고를 한 번에 모아 검수한 뒤 등록하고, 한 달 단위로 추가·수정하는 편이 관리 부담이 작습니다. 사이트가 매일 자동으로 카카오 메시지를 보내지는 않습니다. 친구에게 메시지를 보내는 것은 카카오 채널 관리자센터에서 별도로 진행하며 유료일 수 있습니다.

## 매출을 받기 전에 완성할 것

1. **판매할 실제 결과물:** 현재 가상 샘플을 대체할 개인별 해설의 계산·작성·검수 기준을 결정합니다. 어떤 사람에게 어떤 정보로 어떤 결과물을 제공할지 확정합니다.
2. **결제 제공자:** 운영 주체와 가입 상태에 맞는 PG/결제 서비스, 상점 정보, 판매·환불 기준을 준비합니다.
3. **주문·자동 전달:** 서버에서 결제를 확인한 주문만 생성하고 결과를 전달합니다. 중복 결제, 생성 실패, 환불을 처리합니다.
4. **재열람:** 연락처 소유를 확인하고 해당 주문만 복구합니다. 생년월일만으로 결과를 열어주지 않습니다.
5. **운영 화면:** 글 등록·수정·예약/공개/비공개, 주문 상태·생성 실패·환불을 관리합니다. 실제 관리자만 접근해야 하며, 링크를 숨기는 것으로 보안을 대신하지 않습니다.
6. **성과 측정:** 방문·무료 체험 완료·결제 시작·구매 완료·환불을 구분합니다. 지금은 이 집계가 없습니다.

현재 구매 버튼을 활성화하는 것만으로 이 기능들이 생기지는 않습니다. 판매용 결과물·제공 방식이 준비된 뒤 결제 서비스를 연결합니다. 광고 역시 현재 미연결이며, 설치형 앱 전면광고가 Firebase 웹에 자동으로 붙지는 않습니다.

## 매일 확인할 최소 항목

- 무료 운영 단계: 글과 공유 링크가 열리는지, 원고 오류가 없는지 확인
- 판매 시작 이후: 결제된 주문의 결과가 전달됐는지, 실패·환불·문의가 남아 있는지 확인
- 월간: 신규 글 일괄 검수·등록, 유입 비용과 실제 판매 이익 비교

회원가입 없는 화면이어도 구매 오류를 처리할 지원 경로는 남겨야 합니다. 판매 단계의 상세 서버 요구사항은 `docs/production.md`에 있습니다.
